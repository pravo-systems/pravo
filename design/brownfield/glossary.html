Glossary

Every term used on this site, in alphabetical order. Each entry gives a plain meaning, then a picture from the toy room, then the technical meaning for engineers. Every entry has its own link, so other pages can point straight to it.

How to read an entry

The big line is the plain meaning. The line marked Like is a comparison with the toy room that the whole site uses. The line marked Technical is what an engineer needs.

The toy room, in one breath

Many children share one room. Toys in labelled boxes are written on the list: pravo manages them. Toys on the floor are the shadow estate: they are in the room and not on the list. The neighbour's toys are to be left alone. Onboarding means picking a toy up, labelling it, writing its name on the list, and checking that the list matches the room.

Words marked verified or unverified elsewhere on the site follow the definitions in the entry for verified and unverified.

A

account

The cloud login that owns a set of things. One company can have several.

Like The whole toy room, with its own front-door key.

Technical The unit that owns cloud objects and is billed for them. In aws it has a twelve digit id. A pravo scope names one account and one region.

address

The name pravo gives a thing in your files.

Like The label on the outside of the box.

Technical A CUE path, for example adopted.s3_bucket."legacy-logs-2019". It is a human handle. Matching to the real object is by identity or id and never by address, so renaming a label before the first apply costs nothing.

adopt

Turn a thing lying on the floor into a labelled toy that is on the list.

Like Pick up the toy, give it a label, write its name on the list, then check the list matches the room.

Technical pravo adopt. It reads the object in memory, generates CUE with $import, validates, pins differences, runs the empty-plan gate in a scratch overlay and only then writes a file. Landing is an ordinary saved plan and apply. See gate and hydrate.

agent

An AI helper that can read, search and suggest.

Like A fast helper who points at toys and suggests labels, and never holds the keys.

Technical Software driven by a model that uses pravo's read-only tools (pravo mcp) and edits files. It may propose ignore rules, scope, ids files, pins and pull request text. It may not write the ledger, the state or the cloud, apply anything except a saved plan, or choose a secret. A person merges.

apply

Make the plan real.

Like Do what the list says, once someone has read it.

Technical pravo apply PLAN. Adoption ends with an apply even when the plan changes nothing, because only an apply writes the dependency edges and the config hash of an adopted record.

assumption

A number the designers chose and expect to change.

Like A guess written in pencil.

Technical One of three marks in the design: verified, unverified and assumption. Examples: a batch of 50, three pin rounds, a limit of 10,000 per shard. They are tuned on real data in phase 0.

B

bucket

A folder in the cloud where you keep files.

Like A big cupboard in the toy room with a name on the door.

Technical An object store container, for example an S3 bucket in aws. In this site the resource type is aws_s3_bucket.

backend

The place where pravo keeps its saved records.

Like The cupboard where the lists are stored.

Technical The storage behind pravo.state: a local directory or an S3 bucket. The ledger lives under inventory/ in it, or on a separate backend if you set $discover.ledger.

batch

A small group of things adopted together.

Like One tray of toys carried across the room.

Technical Whatever one adopt run writes. Default cap about 50 (assumption), one pull request. A thousand objects are twenty batches, and they land one after another.

brownfield

A project where things already exist.

Like A room that is already full of toys.

Technical A project that starts from existing infrastructure: some in OpenTofu or Terraform, some made in a console, some made by another team's pipeline. The opposite is greenfield.

C

cloud

Computers, storage and databases that you rent and reach over the internet.

Like The whole toy room, which belongs to a landlord and is shared out in pieces.

Technical A provider account (for example one aws account and region) and everything created in it. Also called the estate.

claimed

An older name for declared. This site now says declared everywhere.

Like The toy is in your hands but has no label yet.

Technical The name this site's colours use for the stage the design calls declared: an $import exists in the specification and no record does.

ClickOps

Making cloud things by clicking in a web page.

Like Building with your hands instead of from instructions.

Technical Informal word for infrastructure created through a web console, which leaves no code or record behind.

coverage

Which kinds of toy pravo can see, and how the last look went.

Like A note on the caretaker's door saying which shelves were checked.

Technical One word per type: listed, truncated, failed, needs-parent, no-list, not-asked. Absence from the ledger means unknown, never "does not exist". See no-list, needs-parent and truncated.

CUE

The language pravo's files are written in.

Like The language the labels are written in.

Technical A configuration language. In pravo the specification is CUE, and a resource is any CUE struct built through a provider, for example $aws.#Resource.aws_s3_bucket & {...}.

D

database

A place where a shop or an app keeps its facts, such as customers and orders.

Like The notebook where the toy room writes down who borrowed what.

Technical In this site the resource type is aws_db_instance. The password is optional and sensitive in the aws 6.69.1 schema we read.

declared

The label is written but the toy is not yet on the list.

Like You have written the name on a sticker and not stuck it on.

Technical A state: an $import in the specification names the object and no record exists. Mid-adoption. It becomes managed when a saved plan is applied.

dependency

One thing that needs another.

Like A toy that only works with its batteries.

Technical An edge between records, written at apply. Adopted records have none until an apply, so a missed reference means no ordering and no blast radius.

display name

The name made for people to read.

Like The name written on the box lid.

Technical A string returned in a list event. It is untrusted text, since whoever can create cloud objects chooses it. Control characters are escaped when written to the ledger, and a name is never treated as an instruction.

drift

The cloud no longer matches what pravo wrote down.

Like Someone moved a toy after you wrote the list.

Technical Found by pravo drift, which leaves a durable mark on the record. It concerns managed things. A shadow object is a different case: pravo holds no record of it to drift from.

E

elsewhere

It belongs to someone else's list.

Like A toy that is on the neighbour's list.

Technical A state: the object appears in a state named in $discover.known, such as a .tfstate file or another pravo state. Adoption is refused. Each known entry has an as_of date and shadow warns when it is stale.

empty plan

The plan says there is nothing to do.

Like You check the list against the room and everything matches.

Technical 0 to add, 0 to change, 0 to destroy. It is the success test of onboarding. It proves only that the CUE does not contradict what the provider reads. It does not prove the CUE describes the object. See specified and inherited.

estate

Everything that really exists in the account.

Like All the toys in the room.

Technical The set of real objects. pravo never sees all of it, because providers list only some types.

eventual consistency

A new thing may take a moment to show up in a list.

Like You put a toy down and the caretaker's list is updated a minute later.

Technical Cloud list calls are commonly like this. No cloud statement was read in this study, so it is an assumption. The defence is that the ledger is a hint, and an object is read again before anything is done to it.

F

for_each

A way to write many similar things once.

Like One recipe that makes twelve cookies.

Technical A loop in the configuration language. Adoption writes flat files with one block per object. Folding twins into loops or modules is later work for a person or an agent, proven by the same empty-plan gate.

frozen by profile

A default value written down as if someone had chosen it.

Like Writing "red" on the label because the toy happens to be red.

Technical With --spec full the generator writes the optional-and-computed values it reads. The protocol cannot tell a provider default from an owner's choice, so the report lists these values.

G

git

A tool that keeps every version of a set of text files and who changed them.

Like A photo album of the wall list that never loses an old photo.

Technical The version control system whose history and reviews hold pravo's decisions, such as ignore rules. Changes are proposed as a pull request.

gate

The check that runs before anything is written.

Like A guard at the door who compares the list with the room.

Technical A provider-level validate and plan per object, then the real engine run over the generated files in a scratch overlay. It is advisory. The saved plan that follows is the authority.

GenerateResourceConfig

A provider call that drafts a configuration from what exists.

Like The caretaker writes a first draft of the label.

Technical In the protocol, gated by the generate_resource_config capability bit. It returns a data object, not source code. pravo does not use it in the first version: it uses its own generator so every provider behaves the same.

glob

A pattern with a star in it.

Like "Every box whose name starts with Scratch".

Technical In an ignore rule a pattern needs glob: true and expect: N, the number of objects it hides at review time. Extras show as seen (rule overflow).

gone

A mark on a record: the last read did not find the object.

Like A toy that is on your list and not in the room.

Technical A record mark in docs/reference/state-format.md. It is about managed records. The ledger word for an object that vanished from a later complete sweep is unlisted.

greenfield

A new project where nothing exists yet.

Like An empty room.

Technical The opposite of brownfield. Most tools assume it.

H

hole

A blank on the label that a person has to fill in.

Like A line on the form that says "write the secret code here".

Technical A required sensitive or write-only attribute that the API never returns. The generator writes the field as its schema type, so pravo validate fails until a person supplies a source such as pravo.#Env.

hydrate

Fill in the full picture of one thing.

Like Pick the toy up and look at it properly.

Technical ImportResourceState then ReadResource, in memory. The result is never written to the state and never stored in the ledger.

I

infrastructure as code

Describing your cloud in text files, so a tool can build it and keep it the same.

Like Writing a recipe instead of cooking by hand each time.

Technical Declarative configuration (here CUE) that an engine such as pravo, OpenTofu or Terraform compares with reality and applies.

identity

The serial number that says exactly which thing this is.

Like The number on the bottom of the toy. The name on the box can change; this does not.

Technical The provider's own key for an object, versioned separately from the resource schema. For an S3 bucket the bucket name is required and the account and region are optional. The ledger key uses the scope and the required attributes. See UpgradeResourceIdentity.

identity lock

A rule that stops two records owning one thing.

Like Two children cannot both write "mine" on the same toy.

Technical Decision D13. At commit time a record written from an import takes a lock keyed by canonical identity and is refused if another record holds it. It is a second lock kind. It cannot see across roots.

ignore rule

A reviewed note that says "not ours, leave it".

Like A sign on a toy: "neighbour's, do not touch".

Technical CUE under $discover.ignore with a mandatory why. Exact identity is the default match. It can expire. Rules are the only way to make shadow objects disappear from a report, so they are reviewed like code.

import

Bring an existing thing under management.

Like Add a toy that was already in the room to your list.

Technical pravo import ADDR ID and the $import field adopt one object per call, with the provider's id string. adopt builds on the same provider call.

ImportResourceState

A provider call that pulls one existing thing in.

Like Handing the caretaker a serial number and getting the toy back.

Technical Takes a type and an id or an identity and returns one or more imported resources. The state it returns is often a skeleton, so a read follows. Whether aws honours identity-only import is unverified.

inherited

See specified and inherited.

Like The part of the toy you did not write on the label.

Technical An optional-and-computed attribute the CUE leaves null, so the plan takes the prior value.

J

JSON lines

A list with one item per line.

Like A shopping list, one toy per line.

Technical Format of the ids file for sweep --from and adopt --ids. Chosen over tab-separated text because names and ids are untrusted, and a tab or newline in one would corrupt a TSV file.

K

known state

Another list that pravo is told to trust.

Like The neighbour's list, pinned on your wall.

Technical $discover.known: a .tfstate or another pravo state, local or remote, read-only. Objects in it show as elsewhere.

L

ledger

The notebook of what the last looks saw.

Like A walker's notebook: "three toys on the floor on Tuesday".

Technical Sharded JSON pages under inventory/ in the state backend, written only by pravo sweep. It holds identity, display name and times, no attribute values. It is disposable and rebuildable.

list (ListResource)

Ask a provider what it can find.

Like "Tell me everything in the room."

Technical ListResource is a streaming call in the protocol. The request names a list type, its config, a limit and whether to include the full object. Events carry an identity, a display name, an optional object and diagnostics. There is no pagination, total or changed-since marker. ValidateListResourceConfig checks the question first.

M

managed

pravo has a record of it and plans changes to it.

Like A toy in a labelled box, written on the list.

Technical A record in this root's state matches the identity. Managed is computed by matching the ledger against records; it is never stored. Removing the declaration of a managed object plans its deletion unless the record is protected.

MCP

A standard plug that lets an AI helper use a program's tools.

Like A socket on the wall that helpers can plug into.

Technical Model Context Protocol. pravo mcp serves tools to agents. Today it has 13, none of which edits state or applies without a saved plan. The design adds read-only tools for the shadow estate.

module

A reusable bundle of several things.

Like A toy set that comes in its own box.

Technical pravo does not infer modules when it adopts. Moving resources into modules is later work, proven by the same gate.

N

needs-parent

A kind of thing that can only be listed inside another thing.

Like You can only list the cards inside a box if you already know which box.

Technical A coverage word. The list config has a required parent attribute such as rest_api_id. 76 aws list types are like this. Not swept in the first version.

no-list

The provider cannot list this kind of thing.

Like The caretaker shrugs when asked to read out this shelf.

Technical A coverage word. Adoption is by id or file only. True for the great majority of aws types, every Kubernetes type in the cached provider, and any provider built only on the older plugin kit.

O

OpenTofu

An open-source tool that builds cloud things from files.

Like A builder who follows written plans.

Technical pravo drives unmodified OpenTofu and Terraform providers. Identity in import blocks is in the v1.12 line. No tofu query was found in v1.13.2, and the request for it was open on 20 October 2026.

orphan delete

A thing that has no text in your files gets removed.

Like Cross a toy off the list and the caretaker throws it away.

Technical A record with no declaration is planned for deletion. Adopting makes an object destroyable by design. Decision D2 proposes that a protected, undeclared record makes the plan an error instead.

overlay

A scratch copy for trying things safely.

Like Tracing paper laid over the list. You draw on the paper.

Technical Reads fall through to the real state read-only. Writes go to a temporary directory (mode 0700) that is deleted after. Whether such a backend is cheap to build is an assumption.

P

pravo

The tool this site is about: you describe your cloud in text files and it changes the cloud to match, and remembers what it made.

Like The tidier in the toy room.

Technical A CUE-based declarative infrastructure engine written in Go that drives unmodified OpenTofu and Terraform providers over the plugin protocol. The name is lowercase.

pull request

A proposal to change some files, which other people read and approve before it takes effect.

Like Handing your drawing to a friend to check before it goes on the wall.

Technical The review step in git hosting. The design suggests one pull request per batch of adoptions.

pin

Write the value you saw so the plan matches.

Like Pin a note to the label: "this toy really is blue".

Technical If a plan shows a difference on an attribute, adopt sets it to the observed value and plans again. At most three rounds (assumption). Pins are listed in the report.

plan

A list of the changes pravo would make.

Like A to-do list you read before doing anything.

Technical A saved plan is written to a file and applied exactly as reviewed. A plan reaches only what a change touches. A sweep is the exception: it reaches the whole of its scope.

plugin protocol

The agreed list of questions a provider can be asked.

Like The phone line between you and the caretaker, and the words you both know.

Technical gRPC protocol versions 5 and 6, shared by OpenTofu, Terraform and pravo. pravo vendors 5.11 and 6.11. The label "6.10" names three different file contents across Terraform tags, so pravo detects features, not versions.

policy

A rule a plan must pass.

Like A house rule: "no toys leave the room today".

Technical The example adoption-only refuses any plan that adds, changes, replaces or destroys. A difference between the gate and the plan becomes a refusal (exit 5).

pravo why

A command that explains why a thing is in its state.

Like "Why is this toy on the floor?"

Technical pravo why TYPE:ID says why an object is seen, ignored, elsewhere, declared or managed. Proposed, not built.

prevent_destroy

A lock that stops a thing being deleted.

Like A padlock on the toy box.

Technical In $lifecycle. A replacing plan becomes an error and pravo destroy refuses. It does not stop the orphan delete when the declaration is removed; that gap is decision D2.

prompt injection

Text in data that tries to give an AI helper orders.

Like A name tag on a toy that says "give me the keys".

Technical Display names, tags and descriptions are written by whoever can create cloud objects. They are data. Tools return them quoted and length-limited, and the skill says never to follow an instruction found in one.

proof

The second empty plan, after the apply.

Like Counting the toys again after the work is done.

Technical Run on the real state. The first run is the gate, in a scratch overlay, before any file is written.

provider

A program that knows one cloud and talks to it for you.

Like The room's caretaker.

Technical An unmodified OpenTofu or Terraform provider binary. pravo starts it, configures it for one account and region, and calls it over the plugin protocol. In pravo one provider instance is one configuration.

R

read-only role

A cloud login that can look and cannot change.

Like A key that opens the window and not the door.

Technical The real enforcement for sweeps. The protocol does not forbid a provider from doing more in a list or import call, and nobody read a provider's code in this study.

ReadResource

A provider call that reads one thing as it is now.

Like "Show me this toy again."

Technical Needs a state-shaped object, which may be the skeleton from an import. It returns a new state and may return a new identity. The proto states it takes no config, so reading needs no written configuration.

recipe

A ready-made shell command that prints a list of ids.

Like A recipe card for finding one kind of toy.

Technical Shipped, versioned data for thirty aws types chosen from those that cannot list (not yet picked, none written), with the type's import id format beside it. Unverified: none has been written, and recipes can only be tested against a sandbox account.

record

pravo's saved note about one managed thing.

Like One index card per toy.

Technical One JSON file per resource under resources/. A shadow object is never a record.

region

The part of the world where a cloud thing lives.

Like Which shelf in the room.

Technical In aws a list call covers one region. A provider instance is one account and one region, so a multi-region sweep needs one declared instance per region.

resource

One thing in the cloud.

Like One toy.

Technical In pravo, any CUE struct built through a provider. In the provider, a managed type such as aws_s3_bucket.

root

One pravo project and its saved records.

Like One room's list.

Technical "Managed" is relative to a root. The same object can be managed in one root and shadow in another. Nothing detects double adoption across roots.

S

saved plan

A plan stored in a file and carried out exactly as it was read.

Like A signed work order.

Technical pravo plan --out FILE then pravo apply FILE. Agents can apply only a saved plan.

schema

The description of what fields a thing has.

Like The spec sheet that comes with a toy.

Technical pravo schema prints provider schemas. Attributes are required, optional, computed or sensitive. The design extends it with --list TYPE to print list filters.

scope

Which account and which region a sweep looks in.

Like Which room, and which shelf of it.

Technical Declared in $discover with a read-only sweep instance and a manage instance. The account label is a property of the scope.

seen

pravo has noticed it and written it down.

Like A toy on the floor that the walker has put in the notebook.

Technical A state: in the latest ledger shard, no record, no $import, no ignore rule, not in a known state. It is a shadow object nobody has decided about.

sensitive value

A secret, such as a password.

Like The code to the toy cupboard.

Technical The API never returns some, and provider flags are incomplete. Sensitive and write-only values are never emitted into generated files. The agent never chooses a secret and sees values only if the operator allows it.

shadow estate

Things that exist in the cloud and that pravo does not manage.

Like The toys on the floor that nobody put away.

Technical Objects that exist and that no record in this root owns. pravo may list them and may read them when asked to adopt one. It never writes to, tags, plans or deletes one.

shard

One page of the ledger.

Like One page of the walker's notebook, for one shelf.

Technical One type, one provider instance (account and region), one sweep. The unit of cost, age and absence. Shards over 5,000 entries are split into parts with a manifest.

specification

The CUE files that say what you want.

Like The written plan of the room.

Technical The files in the project root. $discover is a proposed top-level field in it that holds decisions: scope, ignore rules and known states.

specified and inherited

How much of the label you wrote and how much you left to the provider.

Like "I wrote 5 lines on the label and left 2 blank."

Technical The gate prints specified N, inherited M per object and warns when M exceeds N, because then the plan is empty because the CUE says little.

state

pravo's saved record of what it manages.

Like The cupboard of index cards.

Technical pravo.state: one JSON record per resource, per-resource locks, plus an inventory/ directory for the ledger. A graph store: a plan reaches only what a change touches.

state identify

A one-time pass that adds serial numbers to old records.

Like Writing the serial number on cards that only had names.

Technical pravo state identify reads each record through the provider and writes an identity field. It is a state write and no cloud write. A type with any unmatched record is never listed as seen.

state rm

Forget a record without touching the real thing.

Like Cross a toy off the list and leave it in the room.

Technical pravo state rm ADDR exists today. It is how a managed object goes back to seen. Remove the text in the same change.

stream

Answers that arrive one at a time.

Like The caretaker reading the list aloud, one toy per sentence.

Technical A server-streaming call. It ends with the gRPC status. A broken stream is a failure and never "no results".

sweep

One run of list calls for chosen kinds of thing.

Like The walker goes round the room once with a notebook.

Technical pravo sweep. Read-only. Full scan of its scope every time, since the protocol has no changed-since marker. Scheduling is the user's: cron or CI.

T

tag

A small label the cloud lets you attach to a thing.

Like A sticker on the toy. Not the same as pravo's address.

Technical Key and value pairs. The list protocol carries none, so a sweep cannot filter by tag unless the provider's own list config offers it.

Terraform

The original tool that builds cloud things from files.

Like The other builder who follows written plans.

Technical Shipped terraform query and list blocks in 1.14.0 (19 November 2025). pravo uses the same provider calls without using either tool.

toy room

The picture this site uses for a cloud account.

Like See the whole site.

Technical Toys in labelled boxes are managed by pravo. Toys on the floor are the shadow estate. The neighbour's toys are ignored or elsewhere. Onboarding is picking a toy up, labelling it, writing its name on the list and checking the list matches the room.

truncated

The list was cut off because it hit the limit.

Like The caretaker stopped reading at toy number 10,000.

Technical A coverage word. If events equal the limit, the shard is marked truncated and the old entries are kept. What a limit of 0 means is unverified.

U

Unimplemented

A provider's way of saying "I do not do that".

Like The caretaker says "not my job".

Technical A gRPC status. Every new call must tolerate it. The scottwinkler shell provider and aws 5.100.0 answer it for identity calls.

unlisted

Seen once, and missing from a later full look.

Like A toy in last week's notebook that is not in this week's.

Technical A ledger state, a hint only. Produced only by a complete shard: the stream ended with success, no error diagnostic appeared, and the count is under the limit. Pruned after 30 days (assumption).

UpgradeResourceIdentity

A provider call that updates an old serial number to the new format.

Like Re-stamping an old serial number in the new style.

Technical Takes a type, an old version and the stored identity as JSON. Entries of differing identity versions are unequal until it has run.

V

virtual machine

A computer that lives in the cloud and that you rent.

Like A play table that appears on demand and goes when you stop paying.

Technical In this site the resource type is aws_instance.

verified and unverified

Checked in this study, or not checked.

Like Seen with your own eyes, or only heard about.

Technical Verified means someone read a file, fetched a page or ran a binary and the source is named. Unverified means nobody did. The design either does not depend on it or has a fallback.

Rebuilt for teams

Multiplayer by design.

The classic tools shine on a laptop. In multiplayer scenarios they break: one state file that every plan reads in full, no record of who changed what. An entire ecosystem of external tools had to cover those gaps. pravo learns from the past but starts from a clean slate, with multiplayer mode built in.

See it

The whole estate in a browser

One command, pravo serve, opens a read-only viewer on your machine. The graph, plans, history, state, policies and traces are in one place. There is nothing to host and nothing to set up.

Change one resource, read one resource

A plan reads only what the change reaches, so its cost follows the change and not the size of the estate. Applies that do not overlap run at the same time, started by different people.

How plans stay small Trust it

Sealed and signed state

State is encrypted to a list of readers and every change is signed. A copy of the bucket shows nothing, and a record that was altered shows up. Readers, writers and admins have different keys.

Find what nothing manages

Most estates were built before the code. pravo discover lists what exists in a scope and sets it against the state, and adopt writes the resource that brings an object under management.

Rebuilt for teams

Built for one person on one laptop. Now built for a team.

The first generation of declarative infrastructure tools got the providers and the plan-and-apply loop right. Around them sit one state file that every plan reads in full, state in plain text, and no record of who changed what. An ecosystem of external tools grew up to cover those gaps. pravo keeps the loop and every provider, and starts the rest from a design that does not have them.

One command draws the graph of modules and resources. Jump through it, see what a saved plan changes, and read the history, the state, the policies and the traces of your runs. It is read-only and local.

Change one resource, read one resource

State is one record per resource, so a plan reads what the change reaches. Applies that do not overlap run at the same time, by different people.

Sealed and signed state

State is encrypted to a list of readers and every change is signed. A copy of the bucket shows nothing, and a record that was altered shows up. Readers, writers and admins have different keys.
